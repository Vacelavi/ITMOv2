# Boardroom

Сайт-агрегатор классических настольных игр: шахматы, шашки, го и нарды.

Все четыре игры доступны в локальном режиме для двух игроков за одним экраном. Бот не используется: после каждого хода управление переходит второму игроку.

## Основной сценарий

Два пользователя хотят сыграть в настольную игру за одним экраном. Первый пользователь открывает каталог, выбирает Го, знакомится с правилами или использует быстрый запуск и начинает партию. Игроки по очереди делают ходы, видят текущего игрока и сообщения о некорректных действиях. После двух пасов появляются результат, количество ходов и продолжительность. Пользователь может начать новую партию или вернуться в каталог.

## Структура

- `frontend/` — React + Vite;
- `backend/` — FastAPI, эндпоинты каталога и проверки здоровья.

## Запуск

Требования: Python 3.11+, Node.js 20+ и npm. Обязательные переменные окружения и секреты отсутствуют.

### Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

API будет доступно на `http://127.0.0.1:8000`, документация — на `/docs`.

### Frontend

В отдельном терминале:

```bash
cd frontend
npm install
npm run dev
```

Откройте `http://localhost:5173`. Vite автоматически проксирует запросы `/api` к backend.

Выберите игру в каталоге. Кнопка «Играть» запускает её сразу с именами по умолчанию, а «Подробнее» открывает правила и настройки игроков. После запуска делайте ходы по очереди; кнопка «Начать заново» сбрасывает текущую доску.

## API

- `GET /api/health` — проверка состояния;
- `GET /api/games` — список игр;
- `GET /api/games/{game_id}` — данные выбранной игры.

## Дизайн-система

В интерфейсе используется библиотека компонентов [shadcn/ui](https://ui.shadcn.com/) на базе Base UI с пресетом Nova. Подключены и используются `Button`, `Input`, `Label`, `Card`, `Alert`, `Skeleton`, `Accordion`, `Dialog`, `Badge` и `Separator`.

Цвета, типографика, скругления и состояния фокуса заданы семантическими CSS-переменными в `frontend/src/theme.css`. Специализированные игровые доски сохраняют собственные стили, но используют общую палитру и focus-состояния.

Интерактивный макет создан в v0: <https://boardroom-ten-psi.vercel.app/>.

Локальный React-интерфейс перенесён именно из этого макета: сохранены журнальная шапка «Игры для двух умов», сетка карточек с игровыми миниатюрами, диалог описания, полноэкранная игровая доска и отдельный экран результата. Прототипные таймеры и статические данные заменены запросами к FastAPI и настоящей локальной логикой игр. Быстрая кнопка «Играть» сохранена как намеренное дополнение к сценарию v0.

При работе с AI использовалось требование: переиспользовать компоненты shadcn/ui и не создавать собственные аналоги стандартных кнопок, карточек, диалогов, уведомлений и индикаторов загрузки. Исключение составляют специализированные игровые доски.

## Реализованные состояния и доступность

- каталог получает данные из `GET /api/games` и показывает загрузку, пустой ответ, ошибку с повторной попыткой и успешный результат;
- перед партией `GET /api/games/{game_id}` проверяет выбранную игру; на время запроса кнопки блокируются, а синхронная блокировка исключает повторный запрос при двойном клике или повторном Enter;
- в диалоге есть подписанные поля имён, проверка длины и совпадения имён, а ошибки связаны с полями через `aria-describedby`;
- интерфейс поддерживает клавиатуру и видимый фокус; на доске го работают стрелки, Enter и пробел, а ссылка «Перейти к действиям игры» позволяет пропустить сетку;
- после двух пасов в го показываются результат, число ходов и продолжительность, затем можно начать новую партию.

## Клиентские тесты

Функциональные компонентные и интеграционные тесты:

```bash
cd frontend
npm test
```

Скриншот-тесты в Chromium:

```bash
npx playwright install chromium  # один раз после npm install
npm run test:visual
```

Все клиентские проверки одной командой:

```bash
npm run test:all
```

Production-сборка:

```bash
npm run build
```

Тесты написаны на Vitest, Testing Library и `user-event`. Ответы FastAPI подменяются объектами того же формата, который возвращают реальные эндпоинты.

Проверяются:

- компоненты каталога, открытие и закрытие диалога, раскрытие правил и нажатия кнопок;
- обязательное имя, минимальная длина и запрет одинаковых имён;
- загрузка с задержкой, пустой ответ, ошибка каталога, повторная попытка и успешный ответ;
- ошибка запуска партии и повторный запуск;
- два синхронных submit-события во время ожидания: запрос `GET /api/games/go` выполняется только один раз;
- основной сценарий целиком: загрузка каталога → быстрый запуск Го → игровая доска → два паса → результат → «Сыграть ещё раз» → возврат в каталог.

Дополнительно сохранены отдельные тесты игровой логики, результата партии, управления доской Го с клавиатуры и подсказок шахматных ходов.

Скриншот-тесты Playwright проверяют семь состояний — каталог, диалог описания, загрузку, пустой ответ, ошибку, доску Го и результат — в двух размерах экрана: desktop 1440×1000 и mobile 390×844. Всего сохранено 14 эталонных PNG в [`frontend/visual-tests/boardroom.visual.spec.js-snapshots`](frontend/visual-tests/boardroom.visual.spec.js-snapshots). Тестовый сценарий находится в [`frontend/visual-tests/boardroom.visual.spec.js`](frontend/visual-tests/boardroom.visual.spec.js), настройки сравнения — в [`frontend/playwright.config.js`](frontend/playwright.config.js).

После намеренного изменения интерфейса эталоны обновляются командой `npm run test:visual:update`. Получившиеся PNG нужно просмотреть перед commit; при обычной проверке используется только `npm run test:visual`, чтобы неожиданное визуальное отличие привело к падению теста.

Последний подтверждённый результат: **25 функциональных тестов и 14 скриншот-тестов прошли**. Полный отчёт сохранён в [docs/TEST_RESULTS.md](docs/TEST_RESULTS.md).

## Демонстрация состояний

В dev-режиме доступны воспроизводимые адреса для показа ревьюверу:

- `/?demo=loading` — загрузка;
- `/?demo=empty` — пустой каталог;
- `/?demo=error` — ошибка и повторная попытка;
- `/?demo=go` — игровая доска;
- `/?demo=result` — результат партии.

Обычный адрес `/` всегда использует настоящий FastAPI. Demo-параметры учитываются только при `npm run dev`.

Готовые изображения находятся в [docs/screenshots](docs/screenshots): каталог, загрузка, пустой ответ, ошибка, доска Го и результат.

## Публикация

Сейчас папка проекта не отслеживается Git. Перед отправкой ссылки ревьюверу выполните из корня `ITMOv2`:

```bash
git add practices/practice_05/board-games-hub
git commit -m "Complete practice 8 Boardroom frontend"
git push origin main
```

Перед commit проверьте `git status` и убедитесь, что в него не попали `.venv`, `node_modules`, `dist` или секреты.
